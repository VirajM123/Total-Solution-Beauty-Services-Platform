# Admin Catalog API Contracts

**Status: implemented behind a fail-closed configuration gate.** The backend mounts the endpoints only when `ADMIN_CATALOG_API_ENABLED=true`, the development MongoDB URI and Admin session secret are configured, and model definitions are loaded; requests also require a ready database connection. Otherwise `/api/*` returns `503 API_NOT_CONFIGURED`. Keep the flag false until actual role permissions are verified. The current workspace has no local database URI or session secret, so no live API/database verification or writes have been performed.

## Common conventions

- Base path: `/api`.
- JSON success envelope: `{ "success": true, "data": ..., "requestId": "..." }`.
- JSON error envelope: `{ "success": false, "error": { "code": "...", "message": "...", "details": [] }, "requestId": "..." }`.
- List query: `page` (1-based, default 1), `limit` (default 25, maximum 100), `search`, `sort` (allowlisted field), and `order` (`asc` or `desc`).
- List response data: `{ "items": [], "pagination": { "page": 1, "limit": 25, "total": 0, "pages": 0 } }`.
- Model collection names and validator compatibility were verified in the read-only database schema audit. Existing role documents, permission values, and Admin user records were not inspected in this phase.
- `price` entered in the UI is rupees. The API write boundary should accept an explicit decimal rupee amount with no more than two fractional digits, convert exactly to integer paise, and persist only after the actual schema confirms its unit. A response should identify its unit (proposed `pricePaise`) to avoid ambiguity.
- Do not accept `createdAt`, `updatedAt`, audit actor, or publication transition history from clients.

## Authentication

| Method/path | Proposed behavior | Authorization |
|---|---|---|
| `POST /api/admin/auth/login` | Authenticate an existing Admin by email/password; establish a secure server-managed session. | Public, trusted Origin required, rate-limited; active Admin account and active role required. |
| `POST /api/admin/auth/logout` | Revoke the current session. | Authenticated Admin with valid CSRF token and trusted Origin. |
| `GET /api/admin/auth/session` | Return the current safe Admin identity and permissions. | Authenticated Admin. |

Approved method: email/password using existing Argon2id hashes and opaque, server-managed sessions in secure HttpOnly SameSite Strict cookies. Sessions default to eight hours (configurable up to 24 hours). State-changing requests require a trusted Origin and CSRF token. Never return password hashes, session secrets, or session tokens. No default account or password is created. Role names and permission strings still require verification against the configured development database.

## Categories

| Method/path | Proposed behavior | Permission |
|---|---|---|
| `GET /api/admin/categories` | Paginated list; optional `search`, `publicationStatus`, `sort`, `order`, `page`, `limit`. | `catalog.categories.read` |
| `GET /api/admin/categories/{categoryId}` | Read one category and safe media metadata. | `catalog.categories.read` |
| `POST /api/admin/categories` | Create a category with `name`, optional `description`, optional `thumbnailMediaId`, optional `displayOrder`, and optional lifecycle `status`. `categoryCode` and `slug` are generated by the server. | `catalog.categories.create` |
| `PATCH /api/admin/categories/{categoryId}` | Update editable fields; server validates uniqueness, lifecycle, and media references. | `catalog.categories.update` |
| `PATCH /api/admin/categories/{categoryId}/status` | Change an allowed publication/active state; lifecycle values must match the verified schema. | `catalog.categories.publish` |
| `GET /api/catalog/categories` | Public list of eligible published categories only, with safe media metadata. | Public read |

Do not hard-delete a category. Reject deletion/archival that would violate existing service references unless a reviewed lifecycle policy explicitly permits the transition.

## Services

| Method/path | Proposed behavior | Permission |
|---|---|---|
| `GET /api/admin/services` | Paginated list; optional `search`, `categoryId`, `publicationStatus`, `serviceAreaId`, `page`, `limit`, `sort`, `order`. | `catalog.services.read` |
| `GET /api/admin/services/{serviceId}` | Read one service and safe media metadata. | `catalog.services.read` |
| `POST /api/admin/services` | Create service with a category reference, name, description, rupee price input, duration, media references, service-area references, skill requirements, and approved status fields. | `catalog.services.create` |
| `PATCH /api/admin/services/{serviceId}` | Update editable fields while preserving booking price snapshots and other historical records. | `catalog.services.update` |
| `PATCH /api/admin/services/{serviceId}/status` | Change allowed publication/availability lifecycle. | `catalog.services.publish` |
| `GET /api/catalog/services` | Public paginated list of published, eligible services; optional category and service-area filters. | Public read |
| `GET /api/catalog/services/{serviceId}` | Return a single published, eligible service only. | Public read |

Validate category existence, paise conversion, duration range, media ownership/type/access, and service-area references. Public responses must omit draft-only/admin-only fields and private media. `priceRupees` is an exact decimal string with at most two fractional digits; responses expose paise as integer strings.

## Media metadata

| Method/path | Proposed behavior | Permission |
|---|---|---|
| `POST /api/admin/media/uploads` | Upload an image through configured backend-controlled object storage; return a media asset ID and safe metadata. The endpoint currently returns `503 STORAGE_NOT_CONFIGURED`; no provider or file-signature validation implementation is configured. | Authenticated Admin with the relevant catalog permission and valid CSRF token |
| `GET /api/admin/media/{mediaAssetId}` | Return safe metadata and authorized preview URL or short-lived signed URL. | Authenticated Admin |

Proposed response metadata: `{ "id": "...", "mediaType": "image", "access": "public_catalog", "contentType": "image/webp", "sizeBytes": 1234, "url": "..." }`. Confirm field names against `media_assets`. Worker identity documents require a separate private policy and must never use public catalog URLs.

## Common errors

| HTTP | Error code | Use |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Invalid field, paise conversion, pagination, or filter |
| 401 | `UNAUTHENTICATED` | Missing, expired, or revoked session |
| 403 | `FORBIDDEN` | Authenticated user lacks permission |
| 404 | `NOT_FOUND` | Resource does not exist or is not eligible for public access |
| 409 | `DUPLICATE_RESOURCE` / `INVALID_STATE_TRANSITION` | Unique code/name conflict or unsupported lifecycle transition |
| 413 | `PAYLOAD_TOO_LARGE` | Upload/request exceeds configured size limit |
| 503 | `API_NOT_CONFIGURED` / `STORAGE_NOT_CONFIGURED` | Feature is intentionally disabled or provider is unavailable |

All Admin writes should emit server-side audit records with actor, action, resource ID, request ID, and timestamp after the audit schema is verified. Never trust audit actor identity supplied in the request.
